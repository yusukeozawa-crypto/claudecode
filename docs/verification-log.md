# 検証記録

このツールが「動くつもり」ではなく「実際に動く」ことをどう確認したかの記録。

QA ツールは **緑であることを根拠に「不具合が無い」と判断する道具** なので、
検知ロジックそのものが壊れていると最も危険な状態になる (静かに見逃す)。
そのため、各検知について次の 2 つを確認している。

1. **壊したページ / データで発火すること** (検知漏れがない)
2. **正常なページで発火しないこと** (誤検知がない)

### セキュリティレビューで見つかった不具合 (12件)

セキュリティ観点で独立レビューを行い、次を修正した。
**検知漏れ (偽陰性) 側の欠陥が複数あった** — 対象サイトの実際の脆弱性を
「問題なし」と報告する状態で、検知漏れは誤検知より危険である。

| # | 不具合 | 影響 |
|---|---|---|
| 28 | CI Artifact に平文のトレースが載る | Authorization ヘッダー・一時トークン・Cookie が repo 読み取り権限で取得できる。**マスキング設計を丸ごと無効化していた** |
| 29 | 安全装置が 1 つの Page にしか効かない | `target="_blank"` の CTA・別 context・`page.request`・リンク検査経由で**申込完了を踏み得る** |
| 30 | リンク検査が禁止 URL を GET する | 本番で `/entry/complete` や `/logout` を実際に叩く恐れ |
| 31 | 禁止 URL の判定が URL 形状に弱い | `?next=/thanks`・末尾スラッシュ・大文字で**遮断をすり抜ける** |
| 32 | 反射型 XSS の検出が偽陰性 | ブラウザの再シリアライズにより、生の HTML を出力するページを「問題なし」と報告 |
| 33 | open redirect の検出が偽陰性 | load 後に発生する遅延遷移を見逃す。検査失敗も黙って合格扱い |
| 34 | `maskUrl` がパス・フラグメントを対象外 | サーバーセッション方式のトークン (`/s/<token>/confirm`) が素のまま残る |
| 35 | 抽出テキストの URL が未マスク + CSV 数式注入 | `reports/text/**` に平文で残り、Excel で開くと数式として解釈される |
| 36 | `errorMessage` が未マスク | Playwright のエラーに含まれる遷移先 URL が平文で JSON に残る |
| 37 | 調査ツールの標準出力が未マスク | 一時トークンが CI ログに出る |
| 38 | モック LP のパストラバーサル | `..%2f` で ROOT 外のファイルを読める (開発用) |
| 39 | ローカルサーバーが `/%` で停止・全インターフェース待ち受け | プロセス停止と、レポート内容のネットワーク公開 |

対応の要点:

- **トレース**: 実サイト対象のジョブは `QA_TRACE=off`。Artifact からも `trace.zip` を除外。
  自己検証ジョブ (モックサイト) は秘密情報を含まないため従来どおり取得する。
- **安全装置**: `installContextGuards` で context 全体 (既存ページ + 今後開くタブ) に設置。
  リンク検査・HTTP 経路プローブも禁止 URL を叩かない。service worker は無効化
  (route で遮断できないため)。
- **禁止 URL 判定**: クエリ/フラグメントを除去し、末尾スラッシュの有無と
  大文字小文字を無視して照合。あわせて設定パターンを厳密化
  (`complete*` は `completed-guide.html` まで遮断してしまうため)。
- **反射検出**: 文字列一致をやめ、ペイロードから要素が生成されたかを DOM 検索で判定。
  検査対象パラメータも拡張し、検査できなかった場合は Medium として記録する。
- **API リクエスト経路**: `route` はブラウザのリクエストにしか効かないため、
  `assertRequestAllowed` を用意してリンク検査などの `fetch` 経路でも
  禁止 URL と書き込みメソッドを拒否する。

修正が実際に穴を閉じたことは自己検査で確認している。

| 確認内容 | 結果 |
|---|---|
| 新しいタブ (target=_blank 相当) で申込完了が遮断される | ✓ (通常ページは開ける) |
| 独自に作った context で申込完了が遮断される | ✓ |
| 7 種の URL 形状で禁止判定できる | ✓ (通常 URL は遮断しない) |
| 反射型 XSS を検出できる (`/broken/reflect`) | ✓ (エスケープ済みページでは検知しない) |
| パストラバーサル (`..%2f`) を拒否する | ✓ (403) |
| 不正エンコーディング (`/%`) でプロセスが落ちない | ✓ (400 を返して継続) |
| レポートサーバーがループバックのみで待ち受ける | ✓ (外部 IP から接続不可) |

## 6. 未検証の項目

環境的な制約により確認できていない項目。導入時に確認が必要。

| 項目 | 理由 | 導入時の確認方法 |
|---|---|---|
| 実サイト (staging / production) に対する実行 | 対象 URL が未設定 | Secrets を設定し `qa` ジョブを手動実行 |
| Firefox / WebKit での実行 | 開発環境からブラウザ本体を取得できなかった | `npx playwright install firefox webkit` 後に実行し、環境ごとの基準画像を作成 |
| AI による文章チェック | 要件によりインターフェースのみ実装 | `utils/ai-text-checker.ts` に実装を登録 |
| 実サイトの代理店仕様 | 実物がないと確定できない | `npm run discover` で実測し `config/agencies.yml` に反映 |
