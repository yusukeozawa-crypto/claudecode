# ブラウザの操作画面 (ローカル Web UI)

`run-qa.cmd` をダブルクリック (macOS / Linux は `npm run ui`) すると、
`http://127.0.0.1:4180` に操作画面が開く。

黒い画面を触らずに、実行・進行確認・結果確認・設定変更・更新ができる。

## 画面の構成

上から順に、判断に必要なものだけを置いている。

| 位置 | 内容 |
|---|---|
| 最上段 | **結論**。「異常なし」/「問題あり — 対応が必要な検知 N 件」を大きく表示 |
| 実行中 | 進捗バーと「いま確認中: 代理店の表示 (118 / 190)」、観点ごとの進み具合 |
| 検査する | 練習用サイト / ステージング / 本番のボタン。各ボタンに前回結果を表示 |
| その他の操作 | 最新版に更新 / 仕様調査 (ステージング・本番) |
| **対応が必要なこと** | 検知内容そのもの。期待・実際・場所 (端末/代理店)・再現URL を並べる |
| 代理店コードごとの結果 | 今回検査したコードごとに観点別の OK / 重大度 |
| これまでの実行 | 過去 20 件の一覧 (日時・対象・結果・検知件数) |
| 対象サイトの設定 | URL・申込サイト URL・ベーシック認証を入力して `.env` に保存 |
| 詳細レポート | 既定では開かない。スクリーンショットやテスト一覧が必要なときだけ開く |

**この画面だけで判断できるようにしている。**
以前はレポート HTML を埋め込んでいたが、判定と代理店一覧が二重に出て
結局レポートを読む形になっていたため、検知内容を画面側に出す形に変えた。

### 「対応が必要なこと」の出し方

- 既定は **Critical / High のみ**表示 (チェックで Medium / Low も出せる)。
  Medium / Low は毎回出る記録なので、既定で隠して件数だけ示す。
- 内容が同じ検知はまとめる。PC と SP、複数の代理店で同じ問題が出ても 1 件として並べ、
  「場所」に端末と代理店を列挙する (同じ行が何十件も並ばないようにする)。

## 仕組み

- `scripts/ui-server.mjs` … Node 標準の `http` のみで動く小さなサーバー。
  外部ライブラリを使わない (追加のインストールを増やさないため)。
- `scripts/ui/index.html` … 画面。外部 CDN を読み込まない。
- 進行状況は `reports/progress.json` を経由する。
  レポーター (`reporters/qa-html-reporter.ts`) が 1 テストごとに更新し、
  画面が 1.5 秒ごとに読む。
- 履歴は `reports/history/*.json` (要約のみ・50 件で打ち切り)。

## 安全のための制限

| 制限 | 理由 |
|---|---|
| `127.0.0.1` のみで待ち受ける | 同じネットワークの他の端末から操作されないようにする |
| 実行できるのは固定リストの npm script のみ | 画面から任意のコマンドを実行させない |
| `reports/` の外のファイルは返さない | 設定ファイルや `.env` を画面から読めないようにする |
| ベーシック認証の値は画面に返さない | 「設定済みかどうか」だけを返す |
| URL はドメインだけを保存する | ページのパスは設定ファイル側が持つ (二重指定を防ぐ) |
| 認証情報の空欄は「変更しない」 | 保存操作で既存の値を消さない |

これらは `npm run selftest:ui` (`scripts/check-ui.mjs`) で自動検査しており、
CI の self-test ジョブでも実行している。

## 止めたいとき

画面の「実行を止める」を押す。検査は `npm` の下で動くため、
子孫プロセスまでまとめて終了させている
(`npm` だけを終了すると検査が動き続け、画面の表示と食い違うため)。

## ポートを変えたい場合

```bash
QA_UI_PORT=4200 npm run ui
```

ブラウザを自動で開かない場合は `QA_UI_NO_OPEN=1` を付ける。
