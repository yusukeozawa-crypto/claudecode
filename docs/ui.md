# ブラウザの操作画面 (ローカル Web UI)

`run-qa.cmd` をダブルクリック (macOS / Linux は `npm run ui`) すると、
`http://127.0.0.1:4180` に操作画面が開く。

黒い画面を触らずに、実行・進行確認・結果確認・設定変更・更新ができる。

## 画面の構成

上から順に、判断に必要なものだけを置いている。

| 位置 | 内容 |
|---|---|
| 最上段 | **結論**。「異常なし」/「問題あり — 対応が必要な検知 N 件」を大きく表示 |
| 実行中 | 進捗バーと「いま確認中: 代理店の表示 (118 / 190)」、観点ごとの進み具合 |
| 検査する | 件数を選んでから、練習用サイト / ステージング / 本番のボタンを押す |
| その他の操作 | 最新版に更新 / 仕様調査 (ステージング・本番) |
| **対応が必要なこと** | 検知内容そのもの。期待・実際・場所 (端末/代理店)・再現URL を並べる |
| **チェックリスト** | 行 = 代理店 / 列 = 検査項目 / セル = ✅ ❌ — の 1 枚の表 |
| **備考** | 保留事項・後日確認・後日仕様変更の覚え書き |
| これまでの実行 | 過去 20 件の一覧 (日時・対象・結果・検知件数) |
| 対象サイトの設定 | URL・申込サイト URL・ベーシック認証を入力して `.env` に保存 |
| 詳細レポート | 既定では開かない。スクリーンショットやテスト一覧が必要なときだけ開く |

**この画面だけで判断できるようにしている。**
以前はレポート HTML を埋め込んでいたが、判定と代理店一覧が二重に出て
結局レポートを読む形になっていたため、検知内容を画面側に出す形に変えた。

## チェックリスト (画面の本体)

代理店コードで変わる仕様は数が限られている。
検知結果を何百件も並べても「全部そろっているか」は読み取れないため、
1 枚の表にしている。

| 代理店コード | 会社名 | みらやく | リダイレクト | 代理店コードの付与 | ヘッダーに代理店名 | フッターに代理店名 | あんしんパック | 申込フォームでコード保持 |
|---|---|---|---|---|---|---|---|---|
| littlefamily03 | 株式会社カカクコム・インシュアランス | ○ | ✅ | ✅ | ✅ | ✅ | — | ✅ |
| littlefamily12 | (みらやく ○ の代理店) | ○ | ✅ | — | ✅ | ✅ | ✅ | ✅ |
| littlefamily25 | (みらやく × の代理店) | × | ✅ | — | ✅ | ✅ | ✅ | ✅ |

| セル | 意味 |
|---|---|
| ✅ | 検査して仕様どおりだった |
| ❌ | 仕様どおりでない (件数を併記。マウスを乗せると実際の値が出る) |
| — | この代理店では対象外の項目 (検査していない) |

**「検知が無いこと」を ✅ にはしない。**
検知が無いことを合格の根拠にすると、検査が動いていないだけの状態を
「問題なし」と表示してしまう。そのため各検査は合否どちらの場合も
結果 (`checkId` 付き) を残し、記録が無い項目は — として区別している。

| 列 | 対象 | 何を見るか |
|---|---|---|
| リダイレクト | 全代理店 | カカクコムは専用 LP (`/lp/service-premium/`) へ飛ぶ。他は通常 LP のまま |
| 代理店コードの付与 | カカクコム | リダイレクト後は URL からコードが消えるため、保存領域・Cookie など置き場所すべてを見る |
| ヘッダーに代理店名 | みらやく ○ / × | ヘッダーに会社名が出る |
| フッターに代理店名 | みらやく ○ / × | 「募集代理店：<会社名>」が出る |
| あんしんパック | みらやく ○ / × | ○ は記載がある / × は記載が一切ない |
| 申込フォームでコード保持 | 全代理店 | 申込ボタンを押して申込サイトへ遷移し、コードが維持されているか (マスト) |

**検査は毎回まっさらな状態から始める。**
代理店コードは Cookie に保存され、残っていると次の検査を
その代理店として表示してしまう (= 不具合を隠す)。
各検査の最初の流入時に残留を確認し、あれば Critical として報告してから消す
(docs/checks.md 7.3)。

表は「今回検査した代理店」だけの行になる (件数は実行ごとに抽選)。
無効コードの検査 (未登録コードで代理店名が出ないこと等) は
実在する代理店ではないため、この表には出さず検知結果の側で扱う。


### 検査する代理店の件数

| 選択 | 件数 | 用途 |
|---|---|---|
| 最小 (既定) | 4 社 (パターンごと 1 社 + 常時 2 社) | 導入中の動作確認。数分で終わる |
| 標準 | 10 社 (パターンごと 3 社) | 通常の運用 |
| 全件 | 211 社 | リリース前など、取りこぼしたくないとき |

**まず最小で「ツールが正しく動くこと」を確定させ、そのあとで増やす。**
件数が多いと、ツール側の問題とサイト側の問題が混ざって切り分けにくい。

設定ファイル (`agency-profiles.yml` の `scope.perProfile`) は書き換えず、
環境変数 `QA_AGENCY_PER_PROFILE` で切り替えている。
コマンドから実行する場合:

```bash
QA_AGENCY_PER_PROFILE=3 npm run test:staging   # 標準
QA_AGENCY_SCOPE=all npm run test:staging        # 全件
```

### 実サイトの検査ではツールの自己検査を回さない

`test:staging` / `test:production` は次を除外している。

| 除外 | 理由 |
|---|---|
| `@selfcheck` | ツール自身の検査。同梱モックと純粋な計算しか見ないため、実サイトの実行では無意味 |
| `@discover` | 仕様調査。必要なときに「仕様調査」ボタンから実行する |
| `@visual` | 実サイトの基準画像が無いため比較できない |

以前は実サイト実行でも自己検査 (188 件) が動いており、
4 社の検査で 340 件という内訳が読めない状態だった。
自己検査は `npm run test:local` / `npm run test:selfcheck` で回す。

### 「対応が必要なこと」の出し方

- 既定は **Critical / High のみ**表示 (チェックで Medium / Low も出せる)。
  Medium / Low は毎回出る記録なので、既定で隠して件数だけ示す。
- 内容が同じ検知はまとめる。PC と SP、複数の代理店で同じ問題が出ても 1 件として並べ、
  「場所」に端末と代理店を列挙する (同じ行が何十件も並ばないようにする)。

## 備考 (保留事項 / 後日確認 / 後日仕様変更)

「今は判断できないこと」「あとで確認すること」「先の仕様変更」を画面に出す。
検査結果とは別の覚え書きで、**検査を 1 回も実行していなくても出る**
(設定ファイルから直接作っているため。忘れないためのものが
「実行しないと見えない」のでは意味がない)。

| 種別 | 意味 |
|---|---|
| 仕様変更 | 先の日付で仕様が変わる。その日以降に再確認する |
| 確認待ち | 誰かに聞く / 実物を見れば分かる |
| 保留 | 判断待ち。決まるまで検査できない |

期日 (`due` / 既知の不具合の `fixedOn`) が来たものは黄色で強調し、
一覧の先頭に出す。放置に気づけるようにするため。

### 手で書くもの: `config/notes.yml`

```yaml
notes:
  - id: kakakucom-redirect-condition
    kind: 確認待ち
    title: カカクコムのリダイレクト条件 (URL のコードか Cookie か)
    detail: >-
      「持った」が URL のコードなのか保存済み Cookie なのかが未確定。
    due: 2026-09-30       # 任意
```

### 自動で出るもの (書き写さない)

手で書き写すと必ず古くなるため、設定から分かるものは自動で拾う。

| 備考 | 生成元 |
|---|---|
| 既知の不具合と修正予定日 (過ぎたら「過ぎました」に変わる) | `config/known-issues.yml` |
| 検査対象外にしている代理店 (コード・会社名・理由) | `config/agencies.yml` の `excludedAgencies` |
| 代理店コードの保存先が未確認 | `config/agency.yml` の `storage.type: none` |
| リダイレクトの実装方式が未実測の件数 | `redirectMechanism: unknown` の代理店 |
| リダイレクト回数が未設定の件数 | `expectedRedirectCount: null` の代理店 |

設定を直せば備考も消える。備考が残っているのは、まだ直っていないということ。

## 仕組み

- `scripts/ui-server.mjs` … Node 標準の `http` のみで動く小さなサーバー。
  外部ライブラリを使わない (追加のインストールを増やさないため)。
- `scripts/ui/index.html` … 画面。外部 CDN を読み込まない。
- 進行状況は `reports/progress.json` を経由する。
  レポーター (`reporters/qa-html-reporter.ts`) が 1 テストごとに更新し、
  画面が 1.5 秒ごとに読む。
- 履歴は `reports/history/*.json` (要約のみ・50 件で打ち切り)。

## 安全のための制限

| 制限 | 理由 |
|---|---|
| `127.0.0.1` のみで待ち受ける | 同じネットワークの他の端末から操作されないようにする |
| 実行できるのは固定リストの npm script のみ | 画面から任意のコマンドを実行させない |
| `reports/` の外のファイルは返さない | 設定ファイルや `.env` を画面から読めないようにする |
| ベーシック認証の値は画面に返さない | 「設定済みかどうか」だけを返す |
| URL はドメインだけを保存する | ページのパスは設定ファイル側が持つ (二重指定を防ぐ) |
| 認証情報の空欄は「変更しない」 | 保存操作で既存の値を消さない |

これらは `npm run selftest:ui` (`scripts/check-ui.mjs`) で自動検査しており、
CI の self-test ジョブでも実行している。

## 更新したあとは開き直す

画面を開いたまま「最新版に更新」を押すと、**画面 (HTML) は新しくなるが、
動いているサーバーは古いまま**になる。選択肢が空になるなど、
表示と動作が食い違う。

そのため更新が終わると画面上部に
「ツールを更新しました。開き直してください」を表示する。
黒いウィンドウを閉じて `run-qa.cmd` を開き直せば解消する。

画面側は、サーバーが選択肢を返さない場合でも既定の選択肢を出す
(操作できない状態にはしない)。

## 止めたいとき

画面の「実行を止める」を押す。検査は `npm` の下で動くため、
子孫プロセスまでまとめて終了させている
(`npm` だけを終了すると検査が動き続け、画面の表示と食い違うため)。

## ポートを変えたい場合

```bash
QA_UI_PORT=4200 npm run ui
```

ブラウザを自動で開かない場合は `QA_UI_NO_OPEN=1` を付ける。
